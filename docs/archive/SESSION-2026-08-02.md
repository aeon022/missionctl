## 2. Cross-Device-Sync — `missionctl-core/syncdir` (Kernstück der Session)

Motivation: budgetctl-Daten zwischen MacBook und diesem Rechner über einen selbst verwalteten Cloud-Ordner (iCloud Drive/Dropbox) syncen — ohne eigenen Server/Abo (Positionierung: "no subscriptions, runs locally").

**Neues Paket `missionctl-core/syncdir`:**
- `JournalMode(shared bool)` — schaltet SQLite von WAL auf Rollback-Journal um, sobald ein Sync-Ordner konfiguriert ist (WAL verteilt echte Daten auf mehrere Dateien, die ein Sync-Client nicht atomar hochladen kann)
- `Acquire`/`Release` — Same-Machine-Lock via `flock(2)`, verhindert gleichzeitiges Schreiben zweier Prozesse
- `ICloudPlaceholder` — erkennt nicht heruntergeladene iCloud-Dateien ("Optimize Mac Storage"), klare Fehlermeldung statt stillem Leerzustand

Erweitert: `missionctl-core/config.ResolveDir`, `missionctl-core/doctor.CheckDataDir`.

**Rollout auf alle 9 Tools:** `data_dir`-Config-Key bzw. `<TOOL>_DATA_DIR`-Env-Var, `doctor`-Sync-Status-Check, pfad-referenzgezählter Lock (wichtige Korrektur unterwegs: `flock` ist nicht reentrant im selben Prozess — mehrere Tools öffnen/schließen den Store pro Operation, ein naiver "einmal pro Prozess"-Lock hätte sich selbst blockiert).

**Nebenbei gefundene und mitgefixte Bugs:**
- timectl hatte taskctls DB-Pfad hart codiert (bricht, sobald taskctl umzieht) → liest jetzt `TASKCTL_DATA_DIR` mit
- postctl: falscher Default-Pfad (`~/.config/postctl` statt `~/.local/share/postctl`, Doku und Code widersprachen sich) → einmalige Migration eingebaut; fehlender `doctor`-Befehl neu angelegt; fehlende WAL/Timeout-Pragmas ergänzt (einziges Tool ohne jede Pragma-Konfiguration)

**Dokumentation:** "Syncing across devices"-Abschnitt in jeder der 9 Tool-READMEs.

**Ein echter Zwischenfall:** `sync.sh` (Umbrella-Repo) hätte beim ersten Lauf fast alle lokalen, ungepushten Commits verworfen — `git submodule update` checkt immer auf den im Umbrella-Index gespeicherten Commit aus, egal was lokal committet ist. Nichts ging verloren (rechtzeitig bemerkt), aber `sync.sh` wurde umgebaut: überspringt jetzt Submodule mit ungepushten Commits statt sie zu überschreiben. Dabei auch einen zweiten Bug gefixt: die Loop-Variable hieß `path`, was in `zsh` mit dem speziellen `$path`/`$PATH`-Array kollidiert und `git`/alle Kommandos lautlos unauffindbar macht.

## 5. postctl — Profile (getrennte Accounts, z.B. Privat/Arbeit)

`--profile <name>` bzw. `POSTCTL_PROFILE`:
- Eigene Config **und** eigene Datenbank pro Profil (`~/.config/postctl/profiles/<name>/`, `~/.local/share/postctl/profiles/<name>/`) — komplett unabhängig vom Default und voneinander
- Wird beim ersten Gebrauch automatisch angelegt, kein extra "create"-Schritt
- `postctl profile list` (alle bekannten Profile, aktives markiert), `postctl profile` (nur aktives anzeigen)
- `doctor` und `config show` zeigen das aktive Profil mit an
- Jedes Profil kann unabhängig über sein eigenes `data_dir` gesynct werden

Getestet mit isoliertem `$HOME`: drei Profile (default/work/privat) mit unterschiedlichen Twitter-Zugangsdaten — keine Vermischung bestätigt.

**Dazu:** Profil-Auswahlbildschirm beim interaktiven TUI-Start (`postctl`/`postctl tui`), wenn kein `--profile` gesetzt ist und mindestens ein benanntes Profil existiert. Nicht-interaktive Befehle (list, post, config, …) überspringen das bewusst, damit Skripte nicht blockieren.
